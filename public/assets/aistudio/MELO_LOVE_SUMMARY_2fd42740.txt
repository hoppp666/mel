================================================================================
MELO_LOVE — ЭТАП 1: STORY DATABASE GENERATOR
Техническая и функциональная сводка работы системы (для перехода ко 2-му шагу)
================================================================================

1. НАЗНАЧЕНИЕ СИСТЕМЫ НА ЭТАПЕ 1
--------------------------------------------------------------------------------
Система MELO_LOVE (Этап 1) — это full-stack приложение для накопления, проверки,
оценки качества и дедупликации базы жизненных сюжетных основ (не готовых статей)
для последующих публикаций в Яндекс Дзене.

Целевой объём библиотеки: 3000 уникальных проверенных записей:
- Коллекция A («Кто здесь прав?»): 1500 дискуссионных сюжетных основ (ID: ML-D-XXXX).
- Коллекция B («Романтические истории»): 1500 жизненных сцен (ID: ML-R-XXXX).

Текущее стартовое состояние после инициализации:
- Всего записей: 50 (25 дискуссионных в партии #1 + 25 романтических в партии #31).
- Статусы: 45 подтверждены (approved), 4 ожидают финальной подписи (pending),
  1 на доработке (needs_revision), 0 отклонено (rejected).
- Дублей в стартовой базе: 0.
- Средний балл качества: 90/100.


2. АРХИТЕКТУРА ПРОЕКТА И КЛЮЧЕВЫЕ МОДУЛИ
--------------------------------------------------------------------------------
Стек: TypeScript, React 19, Tailwind CSS v4, Express, Vite, @google/genai.
Сервер запускается на порту 3000 (в dev: `tsx server.ts` с vite.middlewares,
в prod: `node server.ts` со статикой из `dist/`).

Структура файлов:
- server.ts                   — Express-сервер, все REST API эндпоинты и управление
                                промежуточным состоянием партии на проверке.
- server/storage.ts           — Локальное файловое хранилище (UTF-8), подсчёт метрик,
                                нормализация записей, ротация резервных копий.
- server/geminiBatch.ts       — Серверная генерация новых партий (25–50 сюжетов)
                                через Gemini API (`gemini-4-hydrogen`), передача
                                существующей базы в контекст и опциональный поиск
                                через Google Search grounding.
- server/seedDebate.ts        — Стартовые 25 дискуссионных сюжетов (партия #1).
- server/seedRomantic.ts      — Стартовые 25 романтических сюжетов (партия #31).
- src/shared/types.ts         — Единая TypeScript-схема (26 полей + аналитика).
- src/shared/categories.ts    — Каталог категорий (45 дискуссионных + 44 романтических),
                                таксономия сюжетных механик и справочник зарубежных
                                площадок (Reddit, NYT Modern Love, The Cut).
- src/shared/similarity.ts    — Алгоритм проверки смысловых дублей, расчёт общего
                                балла качества, генератор CSV (UTF-8 BOM) и SQL-схема
                                для будущего подключения Supabase.
- src/services/api.ts         — Клиентский слой запросов к `/api/*`.
- src/App.tsx                 — Каркас панели (сайдбар на 9 разделов + топ-бар).
- src/components/StoryListView.tsx — Каталог коллекций с поиском и фильтрами.
- src/components/StoryModal.tsx    — Паспорт сюжета (все 26 полей), редактирование,
                                     ручное добавление и разрешение дублей.
- src/components/BatchModal.tsx    — Мастер запуска и приёмки следующей партии.
- src/components/Sections.tsx      — Разделы: Общий обзор, Категории, Источники,
                                     Уникальность, Качество, Экспорт, Настройки.


3. ХРАНЕНИЕ ДАННЫХ И РЕЗЕРВНОЕ КОПИРОВАНИЕ (БЕЗ ПОТЕРИ ПРОГРЕССА)
--------------------------------------------------------------------------------
Данные НЕ хранятся только в памяти браузера. Всё сохраняется на серверном диске
в кодировке UTF-8 (атомарная запись через временный файл `.tmp`):

1) `data/melo_love_db.json`
   Основная база: массив `stories`, журнал `batches`, пользовательские категории
   `customCategories` и настройки `settings`.

2) `data/pending_batch.json`
   Промежуточное состояние сгенерированной, но ещё не принятой до конца партии.
   Если закрыть вкладку или перезапустить сервер во время проверки 25–50 сюжетов,
   проверку можно продолжить ровно с того же места.

3) `data/backups/melo_love_backup_*.json`
   Автоматические снимки базы (хранятся последние 15 копий). Создаются при каждом
   подтверждении партии, импорте или вручную в разделе «Экспорт базы». Через UI
   можно восстановить базу из любого снимка.

Готовность к Supabase (для следующих этапов):
- В `src/shared/similarity.ts` заложена константа `SUPABASE_SQL_SCHEMA` с таблицей
  `public.melo_story_plots` и индексами по коллекции, статусу и отпечатку.
- На текущем этапе интерфейс честно указывает, что хранение локальное (облако не
  подключено).


4. СТРУКТУРА ЗАПИСИ (26 ОБЯЗАТЕЛЬНЫХ ПОЛЕЙ + АНАЛИТИКА)
--------------------------------------------------------------------------------
Каждый сюжет (`StoryPlot`) содержит:
 1. id                   — уникальный идентификатор (`ML-D-0001`, `ML-R-0001`).
 2. collection           — `'debate' | 'romantic'`.
 3. category             — основная категория.
 4. subcategory          — узкая подкатегория.
 5. title                — название сюжета.
 6. shortDescription     — краткое описание (1–2 предложения).
 7. fullPlot             — развёрнутая жизненная основа.
 8. participants         — участники (возраст, роли).
 9. setting              — место и обстановка действия.
10. coreConflictOrAction — суть конфликта (A) или ключевого поступка (B).
11. sideAPosition        — позиция стороны A (или мотив инициатора в романтике).
12. sideBPosition        — позиция стороны B (или реакция партнёра в романтике).
13. emotionalMechanism   — психологический/эмоциональный механизм.
14. hiddenExpectation    — скрытое ожидание участников.
15. unexpectedNuance     — деталь, меняющая однозначность оценки.
16. possibleTwist        — возможный поворот или финал.
17. mainTriggerQuestion  — главный вопрос для вовлечения читателей.
18. additionalQuestions  — массив дополнительных вопросов.
19. keywords             — массив ключевых слов.
20. ideaSource           — источник идеи (текстовое описание).
21. sourceUrl            — URL внешнего источника (пусто для оригинальных идей).
22. originType           — `'external' | 'original'`.
23. createdAt            — дата создания (ISO).
24. verificationStatus   — `'pending' | 'approved' | 'needs_revision' | 'rejected'`.
25. usageStatus          — `'unused' | 'drafted' | 'published' | 'archived'`
                           (задел под генератор публикаций на этапе 2!).
26. semanticFingerprint  — нормализованный семантический отпечаток.

Дополнительно сохраняются: `mainTheme`, `plotMechanic`, `uniqueDetails`,
`sourceAnalysisNote`, `batchNumber`, объект `quality` (0–100 + детализация по
критериям + `editorialNote`), `similarityMatches`, `duplicateFlag`.


5. КАК РАБОТАЕТ СИСТЕМА ПРОВЕРКИ УНИКАЛЬНОСТИ (ДЕДУПЛИКАЦИЯ)
--------------------------------------------------------------------------------
Модуль `src/shared/similarity.ts` проверяет сюжеты до их попадания в основную
базу (и при пакетной генерации, и при ручном добавлении, и при импорте JSON):

1) Нормализация текста:
   Токенизация, удаление стоп-слов и общих мета-терминов, облегчённый стемминг
   русских окончаний (`stemRussianWord`) и построение биграмм по ядру конфликта.

2) Взвешенное смысловое сравнение (`findSimilarStories`):
   - Сравнение семантических отпечатков и ключевых тем (`fpSim`).
   - Сравнение ядра конфликта/названия (комбинация Жаккара и коэффициента
     перекрытия `overlapSimilarity`, чтобы ловить даже короткие черновики).
   - Сравнение полного сюжета, скрытых ожиданий и нюансов.
   - Сравнение структурных биграмм + небольшие поправки на совпадение категории
     и сюжетной механики.

3) Поведение при обнаружении дубля (порог по умолчанию 38%, настраивается):
   - Дубликат НЕ сохраняется в базу автоматически (при ручном создании API
     возвращает HTTP 409 с массивом совпадений `matches`; в пакетной генерации
     сюжет помечается флагом `duplicateFlag` в очереди `pending_batch.json`).
   - Редактор видит: ID и заголовок похожего сюжета, % сходства и текстовое
     объяснение причины совпадения.
   - Доступные действия: изменить текст, объединить нюансы с существующей записью
     (`POST /api/stories/merge`), отклонить или сохранить как самостоятельный сюжет.


6. КАК РАБОТАЕТ ПУБЛИЧНЫЙ ПРОЦЕСС «СОЗДАТЬ СЛЕДУЮЩУЮ ПАРТИЮ»
--------------------------------------------------------------------------------
1) Пользователь нажимает кнопку «Создать следующую партию» в верхней панели,
   в обзоре или внутри коллекции.
2) Выбирает:
   - Коллекцию (`debate` или `romantic`);
   - Категорию (конкретную или «Сбалансированный подбор», при котором сервер
     автоматически выбирает категории с наименьшим количеством записей);
   - Размер партии (10 / 25 / 35 / 50, по умолчанию 25);
   - Режим поиска:
     * «Оригинальные жизненные сюжеты» (чистый JSON через `responseSchema`);
     * «Исследование зарубежных источников» (сначала `googleSearch` grounding
       по Reddit/NYT/The Cut, затем переосмысление; `sourceUrl` заполняется
       ТОЛЬКО из подтверждённых `groundingChunks`, выдуманные ссылки исключены).
3) Сервер (`POST /api/batches/generate`) формирует сводку последних 90 активных
   сюжетов этой коллекции (названия, темы, механики) и передаёт её в промпт
   `gemini-4-hydrogen`, чтобы модель не повторяла уже существующие сценарии.
4) Каждый полученный кандидат оценивается моделью по рубрике качества (0–100)
   и прогоняется через `findSimilarStories` как против всей базы на диске, так
   и против уже обработанных кандидатов внутри этой же партии.
5) Партия сохраняется в `data/pending_batch.json`. Редактор просматривает идеи,
   при необходимости правит текст прямо в окне приёмки, отмечает «Принять»,
   «Доработать» или «Отклонить» и нажимает «Сохранить отмеченные решения в базу»
   (`POST /api/batches/commit`).


7. REST API ЭНДПОИНТЫ (ДЛЯ ИНТЕГРАЦИИ СО ВТОРЫМ ШАГОМ)
--------------------------------------------------------------------------------
- GET  /api/database                  — вся база, статистика, журнал партий, бэкапы.
- POST /api/stories/check-similarity  — проверка черновика на дубли без сохранения.
- POST /api/stories                   — ручное добавление (блокирует дубли без forceSave).
- PUT  /api/stories/:id               — обновление всех полей с пересчётом отпечатка.
- PATCH /api/stories/:id/status       — смена `verificationStatus` и `usageStatus`.
- POST /api/stories/merge             — слияние дубля с существующей записью.
- DELETE /api/stories/:id             — удаление сюжета.
- POST /api/uniqueness/rescan         — полное пересканирование базы на повторы.
- POST /api/batches/generate          — генерация новой партии через Gemini.
- PATCH /api/batches/staged/:id       — правка кандидата в текущей очереди приёмки.
- POST /api/batches/commit            — фиксация решений по партии в базу + бэкап.
- DELETE /api/batches/staged          — сброс незавершённой очереди партии.
- POST /api/categories                — добавление пользовательской категории.
- PUT  /api/settings                  — сохранение целей (3000) и порогов.
- POST /api/backup                    — создание ручного снимка на диск.
- POST /api/backup/restore            — откат базы к выбранному снимку.
- POST /api/import                    — импорт JSON с фильтром дублей.
- GET  /api/export/json               — скачивание базы в JSON (UTF-8, фильтры).
- GET  /api/export/csv                — скачивание базы в CSV (UTF-8 BOM).


8. ТОЧКА СТЫКОВКИ ДЛЯ ШАГА 2 (БУДУЩИЕ МОДУЛИ)
--------------------------------------------------------------------------------
На первом этапе сознательно НЕ создавались генератор готовых статей, SEO,
генерация фото, Telegram и автопостинг. Для подключения Шага 2 уже готовы:
- Поле `usageStatus` (`unused` -> `drafted` -> `published` -> `archived`) и метод
  `PATCH /api/stories/:id/status` для пометки взятых в работу сюжетов.
- Структурированный JSON/API доступ к проверенным (`verificationStatus === 'approved'`)
  сюжетам с готовыми полями `fullPlot`, `sideAPosition`, `sideBPosition`,
  `unexpectedNuance`, `possibleTwist`, `mainTriggerQuestion`, `additionalQuestions`.
- SQL-схема `public.melo_story_plots` для миграции на Supabase.
