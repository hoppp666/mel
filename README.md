# MELO_LOVE — Фабрика сюжетных основ и публикаций (Этапы 1–4)

Платформа полного цикла для накопления, смысловой дедупликации, зарубежного исследования, авторской генерации и подготовки публикаций о любви и отношениях в фирменном стиле MELO_LOVE для **Telegram** и **Яндекс Дзена (`@zen_sync_bot`)**.

- **Стек:** React 19, TypeScript, Tailwind CSS v4, Lucide Icons, Motion, Vite 8, Node.js, Express (`server.ts`), Google Gemini (`gemini-4-hydrogen` + резерв `gemini-3.1-flash-lite`) с автоматическим переключением на **GigaChat API** (`GigaChat-2-Pro` → `GigaChat-2` → `GigaChat`).
- **Хранение:** локальные JSON-файлы в `data/*.json` с атомарной записью и ротацией до 15 бэкапов на модуль + готовая 6-табличная SQL-схема для **Supabase** (`supabase/schema.sql`).
- **Подробная техническая сводка проекта:** [`MELO_LOVE_SUMMARY.txt`](./MELO_LOVE_SUMMARY.txt).

> **Важно:** все внешние ключи (`GEMINI_API_KEY`, `GIGACHAT_AUTH_KEY`, `TELEGRAM_BOT_TOKEN`, `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`) **необязательны** для запуска и работы интерфейса. Без ключей работают база сюжетов, ручной редактор, дедупликация, проверка лимитов, режим `Dry-Run` и экспорт файлов. При сбое/перегрузке Gemini (503/429) запрос автоматически переключается на свободные модели и затем на GigaChat (если задан `GIGACHAT_AUTH_KEY`).

## 1. Быстрый локальный запуск

Требуется **Node.js 20+** (рекомендуется Node.js 22).

```bash
npm install
cp .env.example .env
# При необходимости укажите ключи в .env (можно оставить пустыми для работы без внешних API)
npm run dev
```

Приложение откроется по адресу `http://localhost:3000`.

### Проверка качества и автотесты

```bash
npm run lint
npm run build
npx tsx --test tests/research.test.ts tests/content.test.ts tests/publishing.test.ts tests/autonomous.test.ts
```

## 2. Можно ли запустить проект на самом GitHub?

Короткий ответ: **как постоянный сайт с интерфейсом — нет; как фоновый планировщик или временную среду разработки — да.**

Разбор возможностей самого GitHub:

1. **GitHub Pages — НЕ подходит.**  
   GitHub Pages раздаёт только статический HTML/CSS/JS. В MELO_LOVE есть серверная часть на Express (`server.ts`), API-эндпоинты `/api/*`, запись в `data/*.json` и защита серверных ключей — на GitHub Pages это работать не будет.
2. **GitHub Actions — подходит для автономного сбора, генерации, автотестов и расписания публикаций.**  
   В проекте настроены два независимых workflow с общей защитой от гонок (`concurrency: melo-love-autonomous-data`):
   - `.github/workflows/melo-love-research.yml` — **Autonomous Research Scheduler** (каждые 4 часа, настраивается в `cron`, также доступен ручной запуск `workflow_dispatch`): собирает новые материалы из зарубежных источников, выполняет 6-уровневую дедупликацию до вызова AI, сохраняет постоянный реестр `data/processed_materials_registry.json`, состояние партий `data/autonomous_scheduler_state.json`, создаёт новые сюжеты/публикации и коммитит обновления `data/*.json` с `[skip ci]`.
   - `.github/workflows/publishing-queue.yml` — **Publishing Scheduler** (каждые 2 часа, до 12 публикаций в сутки, не более 1 поста за запуск): выполняет отправку готовых публикаций (`status: ready`) в Telegram **только** при включённой переменной `TELEGRAM_AUTO_SEND_ENABLED = true` и настроенных Secrets.  
   У GitHub Actions нет веб-интерфейса для пользователя (для UI используйте Render / Railway / Codespaces).
3. **GitHub Codespaces — подходит для временного запуска в облаке.**  
   Вы можете открыть свой репозиторий в **GitHub Codespaces** (кнопка `Code -> Codespaces -> Create codespace on main`), выполнить `npm install && npm run dev` и открыть интерфейс на порту `3000` по временной ссылке браузера. Но Codespaces — это облачный редактор для разработки (лимитированные бесплатные часы), а не постоянный продакшен-хостинг.

Для постоянной работы веб-интерфейса 24/7 используйте Node.js-хостинг вроде **Render** или **Railway** (см. раздел 6).

## 3. Как загрузить MELO_LOVE на GitHub

### Способ 1. Без консоли (через ZIP-архив из интерфейса)

1. Запустите приложение и перейдите в левом меню в раздел **«Экспорт и миграция»**.
2. Нажмите **«Скачать проект (.zip)»** — скачается `melo_love_project.zip`.  
   Архив уже очищен от `node_modules/`, `dist/`, `.env` с секретами и временных папок бэкапов, но включает весь код (`src/`, `server/`, `tests/`, `scripts/`, `supabase/`, `.github/`) и актуальную базу `data/*.json`.
3. Распакуйте ZIP-архив на компьютер в отдельную папку.
4. Зайдите на [github.com](https://github.com) -> нажмите **`+` -> `New repository`**.
5. Назовите репозиторий (например, `melo-love`), выберите **Private** (рекомендуется для авторской базы и публикаций) и нажмите **Create repository**.
6. На странице нового репозитория нажмите ссылку **`uploading an existing file`** (или `Add file -> Upload files`).
7. Перетащите **содержимое** распакованной папки (папки `.github`, `data`, `public`, `scripts`, `server`, `src`, `supabase`, `tests` и корневые файлы `package.json`, `server.ts`, `tsconfig.json`, `vite.config.ts`, `.env.example`, `.gitignore`, `README.md`, `MELO_LOVE_SUMMARY.txt` и др.) в окно браузера.  
   > **Важно:** перетаскивайте файлы изнутри папки так, чтобы `package.json` и `server.ts` лежали **в корне репозитория**, а не во вложенной папке!
8. Внизу нажмите **Commit changes**.

> Если при загрузке через браузер GitHub не даёт перетащить скрытые папки `.github` и файлы `.gitignore`/`.env.example`, включите в проводнике показ скрытых файлов или используйте Способ 2 через Git.

### Способ 2. Через терминал (Git)

```bash
git init
git add .
# Убедитесь, что файл .env НЕ попал в индекс (он защищён в .gitignore)
git status
git commit -m "MELO_LOVE Stages 1-4 initial commit"
git branch -M main
git remote add origin https://github.com/<ваш-логин>/<имя-репозитория>.git
git push -u origin main
```

**Правило безопасности:** никогда не загружайте на GitHub файл `.env` с реальными токенами и ключами.

## 4. Как настроить GitHub Secrets и Variables

Настройки в GitHub нужны для работы автопроверок и обоих автономных workflow (`.github/workflows/melo-love-research.yml` и `.github/workflows/publishing-queue.yml`). Мониторинг партий, постоянного реестра, логов и безопасной остановки доступен в веб-интерфейсе в разделе **«Автопилот · Планировщик»**.

1. Откройте ваш репозиторий на GitHub.
2. Перейдите во вкладку **Settings** (шестерёнка вверху справа).
3. В левом меню раскройте **Security -> Secrets and variables -> Actions**.

### Вкладка `Secrets` (кнопка `New repository secret`)

Добавьте секреты, которые планируете использовать (все они необязательны до момента подключения конкретной интеграции):

| Имя секрета | Назначение | Обязателен? |
|---|---|---|
| `GEMINI_API_KEY` | Ключ Google Gemini API (`gemini-4-hydrogen` + резерв `gemini-3.1-flash-lite`) | Нет (нужен для автоанализа и генерации) |
| `GIGACHAT_AUTH_KEY` | Authorization key из `developers.sber.ru` (резервный или основной AI, без карты) | Нет (резерв при сбоях Gemini) |
| `GIGACHAT_SCOPE` | Версия доступа GigaChat (`GIGACHAT_API_PERS` по умолчанию для физлиц) | Нет |
| `TELEGRAM_BOT_TOKEN` | Токен бота от `@BotFather` | Нет (только для live-отправки) |
| `TELEGRAM_CHANNEL_ID` | Публичный `@username` канала или числовой ID (`-100...`) | Нет (только для live-отправки) |
| `SUPABASE_URL` | URL проекта Supabase (`https://xxx.supabase.co`) | Нет (только для облачной БД) |
| `SUPABASE_SERVICE_ROLE_KEY` | Service Role ключ Supabase (строго серверный!) | Нет (только для облачной БД) |

### Вкладка `Variables` (кнопка `New repository variable`)

| Имя переменной | Значение | Назначение |
|---|---|---|
| `TELEGRAM_AUTO_SEND_ENABLED` | `false` (по умолчанию) | Главный предохранитель фоновой очереди. Пока стоит `false`, GitHub Actions выполняет только тесты/проверки и **ничего не отправляет в Telegram**. Меняйте на `true` только после полной настройки канала и проверки в `Dry-Run`. |

## 5. Как подключить Telegram-бота и Дзен (`@zen_sync_bot`)

1. **Создайте бота в Telegram:**
   - Откройте `@BotFather`, отправьте `/newbot`, задайте имя и username (должен заканчиваться на `bot`).
   - Скопируйте выданный токен в `TELEGRAM_BOT_TOKEN` (в `.env` / Secrets хостинга / GitHub Secrets).
2. **Создайте публичный Telegram-канал:**
   - Обязательно выберите тип **Публичный канал** с `@username` (личные чаты и закрытые группы для автосинхронизации Дзена не подходят).
   - Перейдите в **Управление каналом -> Администраторы -> Добавить администратора**, найдите своего бота и оставьте право **Публиковать сообщения**.
3. **Свяжите канал с Яндекс Дзеном:**
   - Запустите официального бота Дзена `@zen_sync_bot` в Telegram и подключите ваш Дзен-канал к публичному Telegram-каналу по подсказкам бота.
   - Для автоматического переноса постов в `@zen_sync_bot` должен быть включён режим автосинхронизации (команда `/changemode` в боте).
4. **Проверьте подключение в MELO_LOVE:**
   - Перейдите в **Content Studio -> Настройки Telegram и Дзена**, укажите `@username` канала, сохраните настройки и нажмите **«Проверить бота и канал»** (бот должен определить чат с типом `channel`).
   - Пока тестируете тексты, держите включённым чекбокс **Dry-Run** и выключенной реальную отправку.

## 6. Как запустить проект на хостинге (Render vs Vercel)

### Вариант А: Render (рекомендуется — работает без переделки кода)

MELO_LOVE — это единое Node.js + Express-приложение (`server.ts`), которое раздаёт и API (`/api/*`), и собранный React-интерфейс (`dist/`), и работает с файлами `data/*.json`. На **Render** такая архитектура запускается напрямую.

1. Зарегистрируйтесь на [render.com](https://render.com) через аккаунт GitHub.
2. Нажмите **New + -> Web Service**.
3. Подключите ваш репозиторий `melo-love`.
4. Заполните параметры сервиса:
   - **Language / Runtime:** `Node`
   - **Branch:** `main`
   - **Build Command:**
     ```bash
     npm install --include=dev && npm run build
     ```
     *(флаг `--include=dev` важен, чтобы установились `vite` для сборки и `tsx` для запуска `server.ts`)*
   - **Start Command:**
     ```bash
     NODE_ENV=production npx tsx server.ts
     ```
     *(используйте именно `npx tsx server.ts`, так как в `.ts`-файлах проекта используются ESM-импорты с расширением `.js`)*
5. В разделе **Environment Variables** (по желанию сейчас или позже) добавьте переменные:
   - `NODE_VERSION` = `22`
   - `TELEGRAM_AUTO_SEND_ENABLED` = `false`
   - По мере готовности: `GEMINI_API_KEY`, `GIGACHAT_AUTH_KEY`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHANNEL_ID`, `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`.
6. **Важно про сохранность данных (`data/*.json`):**
   - На бесплатном тарифе Render (Free Instance) диск сбрасывается при каждом перезапуске контейнера или новом деплое — все новые записи, сделанные через интерфейс на сервере, пропадут при рестарте.
   - **Решение 1 (простое на Render):** подключите **Persistent Disk** в настройках Web Service (точка монтирования `/opt/render/project/src/data`, если код лежит в `/opt/render/project/src`, предварительно перенеся стартовые `data/*.json` или экспортировав/импортировав базу после первого старта).
   - **Решение 2 (облачная БД):** выполните SQL из [`supabase/schema.sql`](./supabase/schema.sql) в проекте **Supabase**, добавьте `SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY` в Environment Variables и регулярно скачивайте JSON/ZIP-бэкапы из интерфейса.
7. Нажмите **Deploy Web Service**. После завершения сборки приложение откроется по HTTPS-ссылке вида `https://melo-love.onrender.com`.

*(Альтернативы со схожей моделью Node.js + Express: **Railway**, **Fly.io**, любой **VPS с Node.js 22 + PM2/Nginx**.)*

### Вариант Б: Почему Vercel не подходит «как есть»

**Vercel** ориентирован на статический фронтенд и короткоживущие Serverless Functions с **файловой системой только для чтения** (кроме временного `/tmp`).
- В MELO_LOVE сервер работает как постоянный Express-процесс (`app.listen`), хранит базу в `data/*.json` и держит фоновые задачи (Foreign Research / Story Generator) в памяти процесса.
- На Vercel без переписывания серверной части (разбивки `server.ts` на отдельные `/api/*.ts` serverless-функции и полного переноса всех операций чтения/записи из JSON в внешнюю БД Supabase/PostgreSQL) бэкенд не сможет сохранять данные и корректно выполнять фоновые задачи.
- Поэтому для текущего проекта без переделки архитектуры выбирайте **Render**, **Railway** или **VPS**.

## 7. Лимиты Telegram Bot API и рекомендации по публикации

В Content Studio встроена автоматическая диагностика всех ограничений связки **Telegram -> `@zen_sync_bot` -> Яндекс Дзен**:

### Технические лимиты

| Параметр | Лимит | Как обрабатывается в MELO_LOVE |
|---|---|---|
| Максимум Telegram Bot API (`sendMessage`) | **4096 символов** | Жёсткий потолок протокола Telegram. |
| Безопасный лимит отправки MELO_LOVE | **3800 символов (с пробелами)** | Считается сумма **Заголовок + Основной текст + Финальный вопрос + 3–5 хештегов**. Посты длиннее `3800` **блокируются** от автоотправки и никогда не разрезаются ботом на 2 сообщения. |
| Подпись к посту с картинкой (`caption` в `sendPhoto`) | **1024 символа** | При включённой отметке «с изображением (caption)» отправка длинной статьи как подписи к фото блокируется. |
| Размер медиафайла в Telegram / `@zen_sync_bot` | **до 20 МБ** | Изображения и обложки создаются отдельно от MELO_LOVE (например, в Nano Banana 2.1). |
| Заголовок статьи при синхронизации в Дзене | **до 140 символов** | `@zen_sync_bot` берёт **первое предложение** поста как заголовок статьи. MELO_LOVE проверяет длину первой строки и добавляет точку/знак препинания в конце заголовка, чтобы Дзен не «съел» первый абзац в заголовок. |

### Практические рекомендации по публикациям

1. **Длинные статьи (> 3800 символов) не режьте ради автопостинга.**  
   Ограничение `3800` — это лимит Telegram-доставки, а не самого Дзена. Если история получилась глубокой и превышает `3800` символов:
   - либо нажмите **«AI-сокращение до <= 3800»** в Content Studio для Telegram-версии,
   - либо скачайте материал кнопкой **«Экспорт .txt»** и опубликуйте полную версию напрямую в Дзен-студии с обложкой.
2. **Публикуйте чистый текст (Plain Text) без Markdown.**  
   При синхронизации из Telegram в Дзен разметка `**жирный**`, `__курсив__` и Markdown-ссылки не переносятся как форматирование. Редактор MELO_LOVE предупреждает о таких артефактах заранее.
3. **Не делайте репосты (forward) в канал для Дзена.**  
   `@zen_sync_bot` игнорирует пересланные сообщения из других каналов. Публикация должна выходить напрямую от имени вашего привязанного канала (через бота-администратора или отложенный пост в самом канале).
4. **Используйте 3–5 тематических хештегов.**  
   Избегайте пустых общих тегов вроде `#история` или `#жизнь` без контекста сюжета; включайте хештеги в общий подсчёт длины (`<= 3800`).
5. **Не путайте отправку в Telegram с публикацией в Дзене.**  
   Успешный ответ Telegram Bot API (`message_id`) переводит публикацию в статус **`zen_delivery_unconfirmed`**. Только после того как вы увидите вышедшую статью на канале в Дзене, подтвердите её в очереди (`zen_delivery_verified`) — тогда исходный сюжет в базе получит статус `published` и не уйдёт в работу повторно.
6. **Перед любыми изменениями в продакшене тестируйте в `Dry-Run`.**  
   Всегда проверяйте новый канал, формат текста и очереди в тестовом режиме, а статистику просмотров/дочитываний Дзена вносите в раздел «Аналитика» вручную (или из достоверного экспорта), не опираясь на догадки.
