1. ОБЩАЯ АРХИТЕКТУРА И СТЕК
--------------------------------------------------------------------------------
MELO_LOVE — full-stack content-engineering платформа для накопления, проверки,
дедупликации, зарубежного исследования и отбора сюжетных основ о любви и
отношениях для последующей генерации публикаций (Яндекс Дзен и дальнейшие каналы).

Технологический стек:
- Frontend: React 19, TypeScript, Tailwind CSS v4, Lucide Icons, Motion.
- Backend: Node.js + Express (единый сервер на порту 3000; в dev — `tsx server.ts`
  с `vite.middlewares`, в prod — `NODE_ENV=production node server.ts` со
  статикой `dist/`).
- ИИ-интеграция: официальный серверный SDK `@google/genai` (^3.6.1), модель
  `gemini-4-hydrogen`, опциональный инструмент `googleSearch` grounding. Ключ
  `GEMINI_API_KEY` передаётся только на сервере через переменные окружения.
- Хранилище: локальные файлы JSON в кодировке UTF-8 с атомарной записью (`.tmp`),
  автоматическим резервным копированием и заложенной SQL-схемой для Supabase.

Целевой масштаб базы сюжетов: 3000 уникальных записей:
- Коллекция A («Кто здесь прав?»): цель 1500 дискуссионных основ (`ML-D-xxxx`).
- Коллекция B («Романтические истории»): цель 1500 жизненных сцен (`ML-R-xxxx`).


2. АКТУАЛЬНАЯ СТРУКТУРА ПРОЕКТА
--------------------------------------------------------------------------------
Корень:
- server.ts                          — Express-сервер, инициализация хранилищ,
                                       восстановление прерванных заданий и все
                                       REST API маршруты Этапа 1 и Этапа 2.
- MELO_LOVE_SUMMARY.txt              — настоящая сводка проекта.
- tests/research.test.ts             — модульные автотесты Этапа 2 (node:test).

Серверные модули (`server/`):
- server/storage.ts                  — хранилище основной базы (`melo_love_db.json`),
                                       нормализация записей, расчёт метрик,
                                       ротация до 15 бэкапов в `data/backups/`.
- server/seedDebate.ts               — стартовые 25 дискуссионных сюжетов (партия #1).
- server/seedRomantic.ts             — стартовые 25 романтических сюжетов (партия #31).
- server/geminiBatch.ts              — пакетная генерация новых партий (Этап 1) с
                                       передачей контекста базы и опциональным
                                       `googleSearch` grounding.
- server/researchStorage.ts          — хранилище модуля исследований (источники,
                                       задания, карточки, бэкапы, статистика),
                                       генератор ID (`RES-D-xxxx` / `RES-R-xxxx`).
- server/researchSources.ts          — проверка `robots.txt` и HTTP-доступности,
                                       корректное чтение открытых RSS/Atom-лент и
                                       HTML-статей (без обхода auth/CAPTCHA/paywall).
- server/researchAnalyzer.ts         — ИИ-анализ зарубежных находок, разделение
                                       фактов источника и выводов модели, генерация
                                       оригинальной русской сюжетной основы
                                       (`originType: 'external'`), 100-балльная
                                       оценка по рубрике. Таймаут запроса 25с и
                                       быстрый выход при ошибках квоты 429/quota.
- server/researchEngine.ts           — оркестратор фонового поиска, отмены заданий,
                                       поэтапного сохранения карточек, повторного
                                       анализа, дедупликации и переноса в базу.
- server/zipBuilder.ts               — сборка полного ZIP-архива проекта + базы
                                       без зависимостей для скачивания на GitHub.

Общие модули и клиент (`src/`):
- src/shared/types.ts                — единые TypeScript-типы Этапа 1 и Этапа 2.
- src/shared/categories.ts           — справочники категорий (45 debate / 44 romantic),
                                       сюжетные механики и справочник площадок.
- src/shared/similarity.ts           — двуязычный (RU/EN стоп-слова + русский
                                       стемминг) алгоритм смысловой дедупликации,
                                       расчёт качества, генератор CSV (UTF-8 BOM)
                                       и SQL-схема `SUPABASE_SQL_SCHEMA`.
- src/services/api.ts                — типизированный клиент REST API.
- src/App.tsx                        — оболочка панели: сайдбар на 10 разделов и
                                       верхняя панель запуска/прогресса.
- src/components/StoryListView.tsx   — таблица/карточки коллекций с фильтрами.
- src/components/StoryModal.tsx      — паспорт сюжета (26+ полей, включая
                                       `researchId` и `researchNotes`), редактирование,
                                       ручное создание и разрешение дублей.
- src/components/BatchModal.tsx      — мастер пакетной генерации и приёмки (Этап 1).
- src/components/Sections.tsx        — обзор, категории, справочник источников,
                                       уникальность, аналитика качества, экспорт
                                       (JSON/CSV/ZIP-архив для GitHub), настройки.
- src/components/ForeignResearchSection.tsx — рабочий центр `FOREIGN RESEARCH` с
                                              5 вкладками и live-поллингом заданий.
- src/components/ResearchDetailModal.tsx    — детальная карточка исследования
                                              (5 блоков) и управление очередью.

4. КАК РАБОТАЕТ ЭТАП 1 (STORY DATABASE GENERATOR)
--------------------------------------------------------------------------------
- Хранит сюжетные основы `StoryPlot` (26 обязательных полей + `mainTheme`,
  `plotMechanic`, `uniqueDetails`, `sourceAnalysisNote`, `researchId`,
  `researchNotes`, `quality`, `similarityMatches`, `duplicateFlag`).
- Поддерживает ручное создание/редактирование сюжетов, массовую проверку на дубли
  (`POST /api/uniqueness/rescan`), слияние дубликатов (`POST /api/stories/merge`),
  пользовательские категории, импорт JSON и экспорт JSON/CSV/ZIP.
- Пакетная генерация (`POST /api/batches/generate`) сохраняет черновик партии в
  `data/pending_batch.json`; редактор проверяет, правит и подтверждает сюжеты
  через `POST /api/batches/commit`, что исключает случайное засорение базы.


5. КАК РАБОТАЕТ ЭТАП 2 (FOREIGN RESEARCH ENGINE)
--------------------------------------------------------------------------------
1) Проверка источников и гибридный поиск:
   - Для открытых `robots.txt`-разрешённых источников (`available`) сервер читает
     реальные RSS/Atom-ленты и редакционные HTML-индексы, извлекая очищенный от
     меню и подписей к фото текст статьи, автора, дату и URL.
   - Для оставшихся слотов или ограниченных площадок запускается `Google Search
     Grounding` (`@google/genai`) с фиксацией реальных ссылок из `groundingChunks`.
   - Запрещена генерация вымышленных URL, авторов, дат и цитат; при отказе
     Gemini API сохраняются реальные факты источника с честным статусом ошибки.

2) Аналитическая карточка, переосмысление и 100-балльная оценка:
   - Разбор материала в структурированную карточку (разделение фактов источника
     и выводов модели) + переосмысление в самостоятельную русскую сюжетную
     заготовку (`originType: 'external'`, без дословного перевода и «вирусности»).
   - Градация качества (0–100):
     * 90–100: «Отличная идея»
     * 85–89: «Хорошая идея»
     * 75–84: «Требует проверки»
     * <75: «Рекомендуется доработка или отклонение»

3) Трёхконтурная дедупликация и 7-статусная очередь:
   - Проверка совпадений по: (а) основной базе `STORY DATABASE`, (б) другим
     карточкам `research_results.json`, (в) текущей партии, плюс 99% детектор
     одинакового `sourceUrl`.
   - 7 статусов очереди:
     `research_pending` -> `analysis_completed` -> `idea_generated` ->
     `duplicate_check` -> `awaiting_review` -> `approved_for_database` / `rejected`.
   - При одобрении (`approve`) дубли блокируются HTTP 409 до явного решения
     редактора; принятая идея попадает в `STORY DATABASE` с `originType: 'external'`,
     `verificationStatus: 'pending'`, `usageStatus: 'unused'`, `sourceUrl`,
     `researchId` и `researchNotes`.

7. ПРОВЕРКИ, ТЕКУЩИЕ ОГРАНИЧЕНИЯ И ГОТОВНОСТЬ К ЭТАПУ 3
--------------------------------------------------------------------------------
Проверенные метрики качества сборки:
- `vite build` и `tsc --noEmit`: проходят без ошибок.
- Автотесты `npx tsx --test tests/research.test.ts`: 5/5 пройдены успешно.

Внешние ограничения среды:
- Reddit ограничивает прямое чтение через `robots.txt`; NYT Modern Love возвращает
  HTTP 403; Brides возвращает HTTP 402 — исследование с этих площадок опирается на
  `Google Search Grounding` (требует активного `GEMINI_API_KEY` и доступности модели).
- При временной перегрузке (`503`) или исчерпании квоты (`429`) Gemini API
  найденные открытые материалы сохраняются как заготовки для последующего
  повторного анализа.

Точка стыковки для Этапа 3 (генерация публикаций / дальнейшие модули):
- Готовые для отбора сюжеты выбираются из `data/melo_love_db.json` по фильтрам
  `verificationStatus === 'approved'` и `usageStatus === 'unused'`.
- Жизненный цикл использования уже поддержан в API (`PATCH /api/stories/:id/status`:
  `unused` -> `drafted` -> `published` -> `archived`).
- Все поля `StoryPlot` (`fullPlot`, `sideAPosition`, `sideBPosition`,
  `emotionalMechanism`, `hiddenExpectation`, `unexpectedNuance`, `possibleTwist`,
  `mainTriggerQuestion`, `additionalQuestions`, `researchId`, `sourceUrl`), а также
  SQL-схема `public.melo_story_plots` и ZIP-экспорт проекта готовы к расширению на
  Этапе 3 без переписывания существующих модулей.
